This field guide gives you the 19 AI words to learn first, in the order that builds a true picture, if you are heading into AI engineering and agent orchestration. After that come 78 more terms, one plain line each, sorted by layer so you can skim.

Each of the 19 gets three lines: what it means, why it matters now, and a common myth about it, clearly marked as not true. The path ends on orchestration (designing the whole agent loop) and context engineering (deciding what the model sees at each step), which get the most room. A quick self-check waits at the bottom.

Snapshot

Definitions are current as of November 2026. AI words drift fast; when in doubt, check a glossary from the sources list at the end.

A · The learning path
01

Why the words matter

Most people have heard of AI, but far fewer know what it is doing. In a 2026 Pew Research Center survey of 5,119 U.S. adults, 96% said they had heard at least a little about AI. Yet in an August 2025 Searchlight Institute survey of 2,301 U.S. adults, only 28% knew a chatbot works by guessing which words should come next. Another 45% thought it looks up the exact answer in a database.

If you think AI looks things up, you will trust it like a reference book. It is not one.

That gap matters more for builders. When you wire a model to tools, a wrong mental model turns into a wrong design. So the path below starts with what the model really is, then adds one layer at a time:

02

The engine

Terms 1–4 · what the model actually is.

01

Large language model (LLM)

A huge text model trained to guess the next token (a chunk of text). Do that enough and it picks up grammar, style and a lot of facts, and it also makes things up.

Why now: It is the engine every agent wraps. Everything else on this list sits on top of it.

Common myth (not true): It looks up the exact answer in a database, follows a script, or understands the way a person does.

02

Next-word prediction

The basic job an LLM is trained to do: guess the next token, again and again.

Why now: If this does not click, every later idea (made-up answers, agents, reasoning) sits on a false picture of the model.

Common myth (not true): If it only guesses the next word, it cannot plan, write code or sound smart, so it must be looking facts up.

03

Token

The chunk of text a model actually reads and writes: a word, part of a word, or a character. Use, limits and price are usually counted in tokens.

Why now: Rate limits and context budgets are measured in tokens. You cannot size a prompt or an agent loop without them.

Common myth (not true): The model reads whole words, or a token is a login key or a crypto coin.

04

Inference

The model actually running to produce an answer: the live use, not the earlier training.

Why now: Every step an agent takes is an inference call, and each one costs time and money. It is not the same as training.

Common myth (not true): Chatting with it trains it, or inference means it draws a logical conclusion like a person.

03

What you hand it

Terms 5–7 · the words you control.

05

Prompt

The instruction or question you give the model, and in a fuller sense everything else in that request (files, chat history, hidden instructions).

Why now: It is the basic control surface. Every agent step is a prompt, and vague wording is a common cause of surprising actions.

Common myth (not true): A prompt is only the one line you type, or a fancy prompt turns the model into an expert you no longer need to check.

06

System prompt

Standing instructions placed ahead of your message, usually hidden from the user: the model's job description for that product or agent.

Why now: When you build an agent, this is where the role, the limits and the tool rules live. It is separate from the user's request.

Common myth (not true): The chatbot has no extra instructions, or the system prompt is a secret personality rather than rules and tools.

07

Context window

The model's short-term workspace: how much it can see at once (your question, the chat, files, tool results). Past the limit, earlier parts drop off or get squeezed into a summary.

Why now: Every orchestration choice runs into this cap. It is why you cannot paste everything into an agent and hope.

Common myth (not true): It has a long-term memory of everything you ever said, or it forgets because it is bored.

04

When it is confidently wrong

Term 8 · the failure you design around.

08

Hallucination

A confident, plausible answer that is wrong or made up. The model is doing what it always does, guessing likely tokens, with no check against the real world.

Why now: You cannot let an agent email, book or spend based on an unchecked fact. This is the failure you design around.

Common myth (not true): The AI is seeing pictures in its mind, or only wild answers count.

The word itself confuses people. In the same Searchlight survey, only 51% understood that generative AI can make things up, and 21% took “hallucination” literally, as the AI creating images in its mind.

05

Giving it hands

Terms 9–12 · from talking to doing.

09

API

Short for application programming interface: a defined way for one program to ask another for work. It is how your code calls a model or a tool.

Why now: This is how you hook models and tools together in code, not only in a chat window.

Common myth (not true): An API is an app for people, or you need a special API to unlock the “real” AI.

10

Agent

A model plus tools, permissions and a loop, so it can take several steps toward a goal (search, click, email, book) instead of answering once.

Why now: This is the thing you are learning to build: a model that acts, which is why tools, limits and review matter.

Common myth (not true): Any chatbot with an LLM inside is an agent, or an agent is a little person who cannot make mistakes.

11

Tool use (function calling)

The model picks a predefined tool (search, calendar, email, your API) and fills in its inputs, instead of only writing prose.

Why now: This is how an agent actually does work. Orchestration starts with which tools you expose and what each may do.

Common myth (not true): If it mentions a tool, it already used it, or it can invent a tool that was never connected.

12

Human-in-the-loop

A person reviews or approves certain steps, especially sending, deleting or spending, before the agent finishes them.

Why now: For agents that can email, book or spend, the review step is part of the design, not an optional extra.

Common myth (not true): If a person built the agent, it already has a human in the loop.

06

The attack to design against

Term 13 · why reading and acting together is risky.

13

Prompt injection

Hidden or hostile instructions inside a page, file or email that try to hijack an agent that reads them and can also use tools.

Why now: Once an agent reads untrusted text and can take actions, this is the main attack you design against.

Common myth (not true): It is the same as a wording trick you type yourself, or only badly built agents fall for it.

Prompt injection sits at the top of the OWASP Top 10 for large language model applications, a widely used security checklist. The practical defenses are mostly design choices: give agents the fewest tools they need, treat anything they read as data rather than orders, and keep a person in the loop for risky steps.

07

Making it useful

Terms 14–17 · the patterns that turn a demo into a tool.

14

RAG (retrieval-augmented generation)

Look something up first (your files, a database, the web), then have the model write its answer from what was found.

Why now: It is the usual way to give an agent fresh, checkable facts without retraining it, and a core orchestration pattern.

Common myth (not true): RAG means the model can no longer make things up, or it is the same as fine-tuning.

15

Memory

Notes or facts saved on purpose and fed back in later. The LLM itself keeps nothing once a chat leaves the window.

Why now: You decide what carries over between sessions. It is not free, and it is not the same as the context window.

Common myth (not true): The model remembers everything like a person, or “memory” means its weights changed.

16

Structured output

Making the model answer in a fixed format, such as JSON (a simple text format programs can read), a table or a form, so other software can use it reliably.

Why now: Agents that call tools or fill forms need machine-readable answers, not a friendly paragraph.

Common myth (not true): If it sounds confident and well written, your app can already trust the text.

17

Evaluation (evals)

Repeatable tests of whether a model or agent actually does the job, not one demo that went well.

Why now: You cannot improve or safely ship an agent without tests you can rerun after every change.

Common myth (not true): A glowing demo or a leaderboard score means it will handle your messy real inputs.

08

Orchestration

Term 18 · the shape of the whole job.

18

Orchestration (workflow)

The design of the whole loop: which model, which tools, in what order, with what checks, retries and hand-offs to a person.

Why now: This is the job itself: not one clever prompt, but the system of steps, tools and guardrails around the model.

Common myth (not true): Orchestration is just chaining prompts, or once you have an agent you no longer need a workflow.

One agent step in a well-orchestrated loop looks like this:

Planpick the next step
→
Actcall one tool
→
Checktest the result
→
Aska person, if risky

Orchestration decides the order and the checks. Context engineering, next, decides what the model sees at every one of those steps.

09

Context engineering

Term 19 · the capstone of the path.

19

Context engineering

Choosing everything that goes into the model's window (rules, files, memory, tool results, past messages) and what to leave out, so the next step is focused and true.

Why now: It is the capstone skill of agent orchestration, and it ties the whole list together: prompts, memory, RAG, tools and the window.

Common myth (not true): It is a fancier name for prompt engineering, or it means retraining the model.

What it means, in one breath

A model only knows what is in its context window at that moment. Context engineering is the work of choosing that window’s contents for every single step: what to put in, what to leave out, and in what shape. The AI company Anthropic describes it as “the natural progression of prompt engineering” and sums up the goal as finding “the smallest possible set of high-signal tokens” that make the result you want most likely.

RAG is the open-book test. Context engineering is everything else you hand the student before the test.

Why less is often more

A bigger window does not mean the model uses all of it well. In July 2025, the database company Chroma tested 18 LLMs and found that performance grew less reliable as input length grew, even on simple tasks. In one test, models answered questions about a long chat far better when given only the relevant part (about 300 tokens) than when given the full history (about 113,000 tokens). This slide is often called context rot.

Three moves for long jobs

When a task runs longer than one window can hold, Anthropic’s guide describes three common techniques:

  • Compaction: summarize the conversation as it nears the limit, then start a fresh window with the summary.
  • Structured note-taking: the agent writes notes to a file outside the window and reads them back later. This is memory done on purpose.
  • Sub-agents: hand a focused job to a helper agent with a clean window, and take back only a short summary of what it found.

One step, engineered

Say an agent must answer, “Which of our three suppliers can deliver by Friday?” A well-engineered window for that one step might hold:

In
  • Rules: answer only from supplied facts; say “not sure” if missing
  • The question
  • The three suppliers’ latest delivery notes
  • Today’s date
Left out
  • Last month’s unrelated chat
  • Every old supplier email
  • Tools it cannot need here, such as “send email”
  • Untrusted text it has not been told how to treat

Leaving the send tool out is not only tidier. It also means a hidden instruction in a supplier note cannot trigger an email, so context engineering doubles as a safety layer.

Key terms
Context engineering
Choosing what the model sees at each step, and what it does not.
Context rot
Answers slipping as the input grows, before the window is full.
Compaction
Summarizing a long history into a fresh, shorter window.
Sub-agent
A helper agent with its own clean window that reports back a summary.

The big words

The words you hear in every headline, sorted out.

One line per term. Next means learn soon after the path; Later means good to recognize in the news.

Artificial intelligence (AI) Next
The umbrella name for computers doing tasks that used to take human judgment: writing, seeing, planning, talking.
Machine learning Next
A way to build AI by finding patterns in examples, instead of writing every rule by hand.
Deep learning Next
Machine learning that uses large, many-layer neural networks to learn complicated patterns from lots of data.
Neural network Next
A setup of simple connected units (loosely inspired by brain cells) that learn by adjusting connection strengths.
Algorithm Next
A step-by-step recipe a computer follows to finish a task.
Model Next
The trained program that actually produces the answer: the thing behind the chatbot window.
Generative AI Next
AI that makes new text, images, audio, or video, instead of only labeling or retrieving something that already exists.
Chatbot Next
The thing you actually talk to, usually a chat window sitting on top of a model.
Foundation model Next
A large general-purpose model trained on a wide range of data, then adapted for many different jobs.
Artificial general intelligence (AGI) Later
A much-debated label for AI with human-level (or broader) ability across many kinds of tasks; there is no single agreed test.
Superintelligence (ASI) Later
Hypothetical AI that is far more capable than humans at almost every cognitive task.
Narrow AI Later
AI built for one limited job (a spam filter, photo search, a chess engine), not a general stand-in for a person.
11

Inside the engine

What happens between your question and its answer.

Transformer Next
The neural-network design behind most modern LLMs; it uses attention to weigh how parts of the input relate.
Tokenization Next
The step that splits text into tokens before the model sees it.
Parameters (weights) Next
The billions of numbers inside a model, adjusted during training, that shape how it behaves.
Attention Next
A method that lets the model weigh which parts of the input matter most when it produces the next token.
Embedding Next
A list of numbers that represents a word, sentence, or image so similar things sit closer together.
Temperature Next
A setting that makes the model's word choices more focused (lower) or more varied (higher).
Reasoning model Next
A model or mode that spends extra work on in-between steps before answering; better on hard problems, still able to be wrong.
Knowledge cutoff Next
The date after which a model's training data no longer includes world events, unless a tool (search, RAG, a file) feeds it newer information.
Multimodal Next
The model can take in or produce more than one kind of input or output: text, images, audio, video, PDFs.
Scaling laws Later
Rough patterns in how performance often improves as you add data, parameters or compute; not a guarantee.
12

How it learned

Where a model's habits come from, before you ever type a word.

Training (pretraining) Next
The expensive, one-time-ish process of adjusting a model's weights on a huge pile of data so it learns to predict tokens.
Fine-tuning Next
Extra training on a smaller, more specific set of examples so a general model gets better at a particular job.
RLHF Next
Reinforcement learning from human feedback: people rate answers, and those ratings steer the model's later behavior.
Distillation Later
Training a smaller model to copy a larger one's behavior, so it is cheaper or faster to run.
Training data Next
The examples (text, images, audio and more) used to teach a model, often a huge slice of the public web plus other sources.
Bias (in AI) Next
Systematic skew in data or behavior: the model's normal is whatever showed up most, or what it was rewarded for, which may not match your world.
Synthetic data Later
Examples made by a model or a simulation, used as training or test data, rather than collected only from the real world.
Overfitting Later
The model memorizes its training examples too closely, including noise, and then does worse on new cases.
Trained on the web (copyright) Next
Many large models were trained on text and images from the public internet, which raises unsettled legal and ethical questions about whose work was used.
Model collapse Later
A feared or observed drop in quality when models are trained too much on AI-made data instead of fresh human data.
13

What you hand it

The craft around the window, beyond the path's core terms.

Prompt engineering Next
The craft of writing clear requests: the goal, the format, examples, and what done looks like.
Context rot Next
Answers getting worse as the prompt grows, often before the window is actually full.
Few-shot and zero-shot Next
Few-shot: you show a couple of examples so it follows the pattern. Zero-shot: you give the task with none.
Grounding Next
Tying the answer to a real source you provided or retrieved, so it is less likely to invent a fact.
14

Agents and products

Names for the ways models get packaged and put to work.

Model Context Protocol (MCP) Next
An open standard for plugging an AI app into tools and data sources through one common interface.
Copilot Next
A product pattern: AI sitting beside you in an app (mail, docs, code) suggesting or drafting, with you still in charge.
Computer-use or browser agent Next
An agent that can click, type, and navigate a computer or website as if it were using the screen.
Benchmark Next
A standard test used to compare models on a task such as math or coding; useful, and easy to overclaim.
15

The hardware underneath

Where models actually run, and what that costs.

Latency Next
How long you wait for an answer or a step to finish.
Data center Next
A warehouse of servers where a lot of training and most large-model answers actually run.
GPU Next
A chip first made for graphics that is very good at the parallel math models need; data centers are packed with them.
On-device AI Next
The model (or part of it) runs on the phone or laptop itself, which can be faster, more private, and more limited than a data-center model.
Open source vs open weights Next
Open weights means you can download the trained numbers; open source, strictly, also shares the code and recipe.
Closed (proprietary) model Next
You can use it through an app or API, but you cannot download the weights or fully inspect how it was built.
Compute Next
The chip-time and electricity it takes to train or run a model.
TPU Later
A specialized chip, originally from Google, built to speed up machine-learning math.
16

Safety and trust

The words for what can go wrong, and the work that limits it.

Data poisoning Later
An attack that slips bad or mislabeled examples into training or retrieval data so the system behaves in a way the attacker wants.
Alignment Next
The work of making a system behave the way people actually intend: their values, rules and goals.
Guardrails Next
Limits built into the product (refusals, filters, permission checks) meant to block some harmful or off-limits uses.
Jailbreak Later
A trick in the wording of a prompt that tries to get the model to ignore its safety rules.
Deepfake Next
AI-made or AI-altered audio, image, or video that looks or sounds like a real person or event.
Voice clone Next
A model trained or prompted on a short sample of someone's voice so it can say new sentences in that voice.
Sycophancy Next
The model agrees with you or flatters you because that pattern was common in training and feedback, not because you are right.
Privacy Next
What happens to what you type, upload, or say: whether it is stored, used to train, or sent to a server.
AI disclosure (AI label) Next
Telling viewers or users that content was made or altered with AI, often with an official platform label.
Watermark / content credentials Later
A hidden or attached mark meant to show a file was generated or edited, which people and some platforms can later check.
Red teaming Next
A structured attempt to break or misuse a system on purpose, so the builders can find holes before the public does.
17

Hype words

When you hear one of these, ask two questions: what does it actually do, and who checks it?

Agentic Next
An adjective meaning agent-like, able to take steps toward a goal; often used more loosely than “agent.”
AI slop Next
A nickname for low-effort, high-volume AI content that is generic, repetitive, or made mainly to fill a feed.
AI-powered Next
A marketing label meaning some AI is in the product, which might be a real model, a tiny classifier, or almost nothing.
Digital worker / AI employee Later
Sales language for software (often an agent) that is supposed to take over a chunk of a person's job.
Autonomous Next
Able to keep going for a while without a person clicking each step; how much supervision it gets varies a lot.
Frontier model Later
A loosely used name for a leading, highly capable general model at the edge of what labs can train.
World model Later
A system (or a hoped-for system) that keeps an internal picture of how the world works, so it can predict and plan, not only continue text.
Vibe coding Next
Writing software mainly by asking an AI to produce and edit code, guided by what feels right, often with less hand-written code.
The singularity Later
A speculative idea of a tipping point after which AI improvement becomes extremely fast and hard to predict.
AI winter Later
A past (or possible future) period when funding and interest in AI dropped after a wave of hype.
Anthropomorphism (it thinks / knows / understands) Next
Talking about a model as if it had a mind; handy shorthand, misleading if taken literally.
18

AI you already use

Older and quieter AI that was around long before chatbots.

AI detector Next
A tool that claims to guess whether text or media was made by AI; these are often unreliable, especially on short text.
Image generator Next
A model that makes a picture from a text prompt, a sketch, or another image.
Text-to-video Next
A model that makes a short video from a text prompt or a still image.
AI Overview Next
A generated summary at the top of some search results, built from sources the search engine retrieved.
Recommendation system Next
An older, still-huge kind of AI that ranks what you see next (feeds, videos, shopping, music) from patterns in behavior.
Computer vision Next
AI that works on pictures and video: finding faces or objects, reading a scene, spotting a package, and so on.
Speech-to-text Next
Turning spoken audio into written words, often on a phone or in a meeting app.
Autocomplete Next
The older cousin of an LLM: guess the next word or line as you type, in mail, search, or a phone keyboard.

Quick review

Answer out loud first, then tap a question to check.

What is an LLM actually doing when it answers you?
Guessing the next token (a chunk of text), again and again, based on patterns it learned. It is not looking the answer up in a database.
What is a token, and why should a builder care?
The chunk of text a model reads and writes: a word, part of a word, or a character. Limits, context budgets and usually price are counted in tokens.
Is chatting with a model the same as training it?
No. Chatting is inference: the finished model running. Training is the earlier, expensive process that set its weights.
How is a system prompt different from your prompt?
The system prompt is the standing job description (role, limits, tool rules) placed ahead of the user's message, usually hidden.
What happens when a conversation outgrows the context window?
Earlier parts drop off or get squeezed into a summary. The model only sees what fits in the window right now.
Why does a model hallucinate?
It always produces likely-sounding tokens. With no check against real sources, a likely-sounding answer can be wrong.
What turns a chatbot into an agent?
Tools, permissions and a loop, so it can take several steps toward a goal instead of answering once.
What is prompt injection, and one way to limit it?
Hostile instructions hidden in text an agent reads. Limit it by giving the agent only the tools it needs, treating what it reads as data, and keeping a person in the loop for risky steps.
Does RAG stop a model from making things up?
No. It gives the model relevant facts to write from, which helps a lot, but the answer still needs checking.
Does the model remember your last chat by itself?
No. Memory is notes saved on purpose and fed back in later. The model's weights do not change.
Why run evals instead of trusting a good demo?
A demo shows one lucky run. Evals are repeatable tests you rerun after every change, on realistic inputs.
How is context engineering different from prompt engineering?
Prompt engineering is mostly how you word the ask. Context engineering decides everything the model sees at each step (rules, tools, retrieved facts, memory, results, history) and what to leave out.
